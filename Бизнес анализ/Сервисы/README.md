# Сервисы

Карта бэкенд-сервисов платформы. Полное описание границ, взаимодействия и потоков — в [Архитектуре](../../Архитектура.md).

| Сервис | Зона ответственности | Планируемый документ |
|---|---|---|
| API Gateway | Единственная REST-граница, проверка токена, ограничение частоты, трансляция в gRPC | `API Gateway.md` |
| Auth | Идентичность, вход, внешние провайдеры, сессии, роли и разрешения | `Auth.md` |
| Core Education | Профили, расписание, брони, уроки, посещаемость, записи, чаты, уведомления, поддержка | `Core Education.md` |
| Learning | Курсы, программы, группы, зачисления, задания, тесты, материалы, прогресс | `Learning.md` |
| Billing | Журнал операций, резервы, пакеты, тарифы и комиссии, выплаты | `Billing.md` |
| Realtime | WebSocket-хаб, журнал доски, чат комнаты, присутствие | `Realtime.md` |

## Внешние зависимости

| Система | Назначение | Этап |
|---|---|---|
| LiveKit | Видео, аудио, демонстрация экрана, запись занятий | MVP |
| S3-совместимое хранилище | Файлы, вложения, материалы, записи, снимки доски | MVP |
| OAuth-провайдеры | Вход через внешние аккаунты | MVP |
| Платёжный шлюз | Приём платежей, возвраты, фискализация | Завершающая стадия |
| Сервис массовых выплат | Выплаты преподавателям | Завершающая стадия |

## Структура документа сервиса

1. Назначение и зона ответственности (владеет / не владеет)
2. Внутренние модули
3. Внешний и внутренний API
4. Публикуемые и потребляемые события
5. Данные: ключевые сущности и инварианты
6. Ключевые потоки
7. Правила доступа
8. Чего в сервисе нет и почему

> Статус: заготовка. Документы по сервисам заполняются после декомпозиции модулей.
