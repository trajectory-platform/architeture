# Карточка пользователя

## 1. Назначение

Рабочее место сотрудника по конкретному аккаунту: посмотреть состояние, понять историю, вмешаться. Карточка собирает данные из всех сервисов платформы, но **не подменяет профильные разделы**: учебные и финансовые сущности показываются сводками со ссылками в свои разделы.

Доступ к карточке: разрешение `auth_user_view`. Отдельные вкладки требуют собственных разрешений (раздел 3).

## 2. Шапка карточки

Видна на всех вкладках, не прокручивается.

| Элемент | Содержание |
|---|---|
| Аватар и имя | Имя и фамилия; для удалённого аккаунта — «Удалённый пользователь» |
| Идентификатор | Полный идентификатор аккаунта, копируется по клику |
| Метки ролей | Ученик, Преподаватель, Представитель |
| Статус аккаунта | Активен, Ожидает подтверждения, Заблокирован, Удаление запланировано, Удалён |
| Плашка предупреждения | Для `blocked`: причина и исполнитель блокировки. Для `deletion_scheduled`: дата удаления и кнопка отмены |
| Кнопки действий | Раздел 4 |

## 3. Вкладки

| Вкладка | Разрешение | Содержание |
|---|---|---|
| Профиль | `auth_user_view` | Учётные данные и данные профиля |
| Роли и доступ | `auth_role_view` | Базовые роли, заявка на преподавателя, связь с представителем или подопечными |
| Сессии | `auth_session_view` | Активные сессии и способы входа — см. [Сессии и безопасность](Сессии%20и%20безопасность.md) |
| Обучение | `student_profile_view` или `teacher_profile_view` | Сводка учебной активности со ссылками в профильные разделы |
| Финансы | `finance_balance_view` | Баланс, резервы, последние операции |
| Обращения | `comms_ticket_view` | Обращения пользователя в поддержку |
| История | `auth_audit_view` | Записи журнала действий по этому аккаунту |

Вкладка без разрешения не отображается.

### 3.1 Вкладка «Профиль»

**Учётные данные** (владелец — сервис Auth):

| Поле | Тип | Редактирование сотрудником | Правила |
|---|---|---|---|
| Идентификатор аккаунта | идентификатор | нет | — |
| Email | email | нет | Смена email — только самим пользователем с подтверждением обоих адресов |
| Email подтверждён | признак | нет | Отображается дата подтверждения |
| Дата регистрации | дата и время | нет | — |
| Способы входа | список | нет | Пароль, Яндекс ID, VK ID, Google; отображается дата привязки |
| Статус аккаунта | перечисление | через действия | Меняется только действиями раздела 4 |

**Данные профиля** (владелец — сервис Core Education), редактируются при `auth_user_edit`:

| Поле | Тип | Обязательное | Правила |
|---|---|---|---|
| Имя | строка | да | 1–60 символов |
| Фамилия | строка | нет | до 60 символов |
| Аватар | изображение | нет | jpg, png, webp; до 5 МБ; сторона до 2048 px |
| Телефон | телефон | нет | Формат российского номера, нормализуется при сохранении, уникальность не требуется |
| Дата рождения | дата | нет | Не в будущем; возраст не более 100 лет |
| Часовой пояс | справочник | да | Из справочника часовых поясов; по умолчанию определяется при регистрации |
| Язык интерфейса | справочник | да | В MVP единственное значение — русский |
| Комментарий сотрудника | текст | нет | До 1000 символов, виден только сотрудникам, не виден пользователю |

Правила редактирования:

1. Изменение любого поля профиля сотрудником требует указания причины (одна строка, до 200 символов) и пишется в журнал действий с прежним и новым значением.
2. Email и способы входа сотрудник не меняет — только пользователь.
3. Поля профиля преподавателя (предметы, цена, описание, видеовизитка) редактируются в разделе [Преподаватели](../Преподаватели/README.md), на этой вкладке отображается ссылка.

### 3.2 Вкладка «Роли и доступ»

**Базовые роли:**

| Элемент | Действие |
|---|---|
| Список ролей с датой выдачи и исполнителем | — |
| Выдать роль «Преподаватель» | `auth_role_edit`, с указанием причины; создаёт заявку сразу в статусе `approved` |
| Отозвать роль «Преподаватель» | `auth_role_edit`, с указанием причины; блокируется при наличии будущих уроков |
| Отозвать роль «Представитель» | `auth_role_edit`; блокируется при наличии активных связей с учениками |

Роль «Ученик» не выдаётся и не отзывается вручную.

**Заявка на роль преподавателя:** статус заявки, дата подачи, дата решения, исполнитель, причина отклонения. Кнопка перехода в карточку модерации раздела «Преподаватели».

**Связи представителя:**

| Для аккаунта | Отображается |
|---|---|
| С ролью «Представитель» | Таблица подопечных: имя, статус аккаунта ученика, дата связи, действие «Отвязать» (`student_representative_edit`) |
| С ролью «Ученик» | Представитель: имя, email, дата связи, действие «Отвязать» |

Отвязка требует указания причины. После отвязки последнего подопечного роль «Представитель» снимается автоматически, аккаунт остаётся.

### 3.3 Вкладка «Обучение»

Сводка без права редактирования, все элементы — ссылки в профильные разделы.

| Блок | Для ученика | Для преподавателя |
|---|---|---|
| Курсы и группы | Список зачислений: курс, группа, преподаватель, статус доступа, дата окончания | Список ведомых курсов и групп |
| Уроки | Счётчики: проведено, отменено, неявок; ближайший урок; последний урок | То же по своим урокам |
| Домашние задания | Выдано, сдано, проверено, просрочено | Очередь непроверенных |
| Прогресс | Процент освоения программы по каждому курсу | — |

### 3.4 Вкладка «Финансы»

| Блок | Содержание |
|---|---|
| Баланс | Доступный баланс, сумма в резерве, итого |
| Пакеты и абонементы | Активные пакеты с остатком занятий, абонементы с датой окончания |
| Последние операции | 20 последних операций: дата, тип, сумма, основание, ссылка на журнал операций |
| Начисления (для преподавателя) | Баланс к выплате, последняя выплата, ссылка в раздел «Финансы» |

Действия «Пополнить баланс» и «Скорректировать баланс» выполняются в разделе [Финансы](../Финансы/README.md) и в карточке пользователя не дублируются: денежная операция требует полей основания и подтверждения, которые живут в финансовом разделе.

### 3.5 Вкладка «Обращения»

Список обращений пользователя в поддержку: номер, категория, тема, статус, дата создания, дата последнего ответа. Переход в карточку обращения раздела [Коммуникации](../Коммуникации/README.md).

### 3.6 Вкладка «История»

Записи [журнала действий](Журнал%20действий.md), у которых этот аккаунт является объектом или исполнителем. Фильтры по типу события и периоду. Пагинация. Экспорт — по `auth_audit_export`.

## 4. Действия над аккаунтом

### 4.1 Блокировка

Разрешение `auth_user_block`. Два независимых уровня.

**Полная блокировка аккаунта.** Применима к любому аккаунту.

| Аспект | Поведение |
|---|---|
| Форма | Обязательная причина: выбор из справочника + комментарий до 500 символов |
| Вход | Запрещён; на форме входа сообщение «Аккаунт заблокирован, обратитесь в поддержку» |
| Сессии | Все активные сессии завершаются немедленно |
| Будущие уроки | Отменяются с причиной «Блокировка участника»; резервы возвращаются на баланс в полном объёме независимо от политики возврата |
| Идущий урок | Не прерывается; блокировка вступает в силу после завершения текущего занятия |
| Баланс | Сохраняется, операции с ним недоступны |
| Чаты и материалы | Сохраняются, доступ закрыт |
| Уведомление | Пользователь и вторая сторона отменённых уроков получают in-app уведомление |

Разблокировка возвращает статус `active`, требует указания причины. Отменённые при блокировке уроки не восстанавливаются.

**Снятие преподавателя с публикации.** Применима только к аккаунтам с ролью «Преподаватель», разрешение `teacher_publication_edit`.

| Аспект | Поведение |
|---|---|
| Каталог | Преподаватель скрыт из каталога и поиска |
| Новые брони | Невозможны; слоты не отображаются ученикам |
| Текущие ученики | Продолжают заниматься: существующие брони, уроки, домашние задания и чаты работают |
| Вход и кабинет | Работают полностью |
| Начисления и выплаты | Работают |

Снятие с публикации — мягкая мера для разбора жалоб без срыва обучения текущих учеников. Полная блокировка — жёсткая, применяется при нарушении, требующем немедленного прекращения работы.

### 4.2 Сброс пароля

Разрешение `auth_credential_reset`. Сотрудник **не задаёт пароль** и не видит его.

1. Сотрудник указывает причину.
2. Текущий пароль признаётся недействительным, все сессии пользователя завершаются.
3. Пользователю отправляется ссылка задания нового пароля со сроком жизни 24 часа.
4. До задания нового пароля вход невозможен; на форме входа отображается подсказка «Пароль сброшен, проверьте почту».
5. Действие пишется в журнал.

Для аккаунта, у которого нет пароля (вход только через внешнего провайдера), действие недоступно с пояснением.

### 4.3 Завершение сессий

Разрешение `auth_session_revoke`. Описано в документе [Сессии и безопасность](Сессии%20и%20безопасность.md).

### 4.4 Просмотр от лица пользователя

Разрешение `auth_user_impersonate`. Режим **только чтение**.

| Правило | Значение |
|---|---|
| Запуск | Из карточки или списка, с обязательным указанием причины (до 200 символов) |
| Что видно | Кабинет пользователя в том виде, в котором его видит пользователь |
| Что запрещено | Любые изменения данных, отправка сообщений, отправка и проверка домашних заданий, вход в комнату урока, денежные операции, изменение профиля и настроек |
| Индикация | Постоянная плашка поверх интерфейса: «Просмотр от лица {имя}. Изменения недоступны», кнопка «Выйти из режима» |
| Срок | Сеанс автоматически завершается через 30 минут |
| Уведомление пользователя | Не отправляется |
| Журнал | Записываются запуск, причина, исполнитель, время начала и завершения |

Технически режим реализуется отдельным короткоживущим токеном с признаком «только чтение» и идентификаторами и сотрудника, и пользователя; сессии пользователя при этом не создаются и в его списке сессий не появляются.

### 4.5 Удаление аккаунта и персональных данных

Разрешение `auth_user_delete`. Заявку подаёт сам пользователь из своего кабинета либо сотрудник по обращению.

**Отсрочка 30 дней.**

1. Аккаунт переходит в статус `deletion_scheduled`, фиксируется дата планового удаления.
2. Будущие уроки отменяются, резервы возвращаются на баланс полностью.
3. Активные сессии завершаются, кроме той, из которой подана заявка.
4. При входе пользователь видит единственный экран: «Аккаунт будет удалён {дата}» и кнопку «Отменить удаление». Остальной функционал недоступен.
5. Отмена возвращает статус `active`; отменённые уроки не восстанавливаются.
6. По истечении 30 дней система выполняет анонимизацию.

**Что затирается при анонимизации:**

| Данные | Действие |
|---|---|
| Email | Заменяется на технический невосстановимый адрес, уникальность сохраняется |
| Пароль и способы входа | Удаляются, привязки внешних аккаунтов разрываются |
| Имя, фамилия, телефон, дата рождения, аватар | Затираются; отображается «Удалённый пользователь» |
| Профиль преподавателя: описание, образование, опыт, видеовизитка | Удаляются |
| Реквизиты выплат | Удаляются |
| Содержимое личных сообщений пользователя | Заменяется на «Сообщение удалено» |
| Файлы: аватар, вложения чатов, сданные работы | Удаляются из хранилища |
| Сессии и токены | Удаляются |

**Что сохраняется обезличенным:**

| Данные | Причина |
|---|---|
| Журнал операций и все денежные записи | Требование неизменяемости финансового журнала; баланс остаётся воспроизводимым |
| Факты проведения уроков, посещаемость, длительность | Основание начислений преподавателю и статистики платформы |
| Оценки и результаты тестов без содержимого работ | Учебная статистика курса и группы |
| Записи журнала действий | Разбор инцидентов; исполнитель заменяется на обезличенный идентификатор |
| Записи уроков | Хранятся один календарный месяц от готовности файла; удаление аккаунта одного участника не удаляет общую запись автоматически |

Правило по записям уроков фиксируется явно: удаление аккаунта не удаляет записи занятий, в которых участвовали другие люди. Пользователь теряет доступ к ним; записи удаляются через один календарный месяц от готовности файла. Отдельный запрос участника на досрочное удаление рассматривает суперадминистратор с причиной и уведомлением участников — см. [карточку урока](../Расписание%20и%20уроки/Карточка%20урока.md). Срок не продлевается из-за удаления аккаунта или повторной обработки готовности файла.

**Блокирующие условия.** Заявка на удаление не принимается, если:

- у преподавателя есть непогашенный баланс к выплате;
- у ученика есть неиспользованный оплаченный остаток на балансе или в пакете;
- есть незакрытые обращения с финансовой категорией.

В этих случаях интерфейс показывает конкретную причину и ссылку на её устранение.

## 5. Правила и ограничения

1. Сотрудник не задаёт и не видит пароли пользователей ни при каких действиях.
2. Смена email выполняется только пользователем.
3. Любое изменение данных пользователя сотрудником требует указания причины и пишется в журнал.
4. Просмотр от лица пользователя не даёт права на действия и не открывает комнату урока.
5. Блокировка не удаляет данные; удаление не отменяет финансовую историю.
6. Будущие уроки отменяются с полным возвратом резерва и при блокировке, и при запланированном удалении — политика возврата в этих случаях не применяется.
7. Денежные действия над балансом выполняются только в разделе «Финансы».
8. Карточка не показывает вкладки, на которые у сотрудника нет разрешения.

## 8. Критерии приёмки

1. Сотрудник с ролью «Менеджер» открывает карточку, видит вкладку «Финансы» без действий и не видит вкладку «История».
2. Попытка сохранить изменение профиля без причины отклоняется, поле подсвечивается.
3. После блокировки: пользователь не входит, его сессии исчезли, все его будущие уроки отменены, резервы вернулись на баланс полностью, вторая сторона получила уведомление.
4. Блокировка участника идущего урока не выкидывает его из комнаты; после завершения занятия вход в систему невозможен.
5. Снятие преподавателя с публикации убирает его из каталога, но урок с уже записанным учеником проходит штатно.
6. Сброс пароля завершает сессии, старый пароль перестаёт работать, письмо со ссылкой приходит, ссылка перестаёт действовать через 24 часа.
7. Кнопка сброса пароля недоступна для аккаунта, входящего только через Яндекс ID, с пояснением.
8. В режиме просмотра от лица все кнопки изменения данных недоступны, попытка прямого запроса на изменение отклоняется сервером, вход в комнату урока невозможен.
9. Режим просмотра от лица автоматически завершается через 30 минут; в журнале есть записи запуска и завершения с причиной.
10. Пользователь с остатком на балансе не может подать заявку на удаление, интерфейс называет причину.
11. Пользователь в статусе `deletion_scheduled` при входе видит только экран с датой удаления и кнопкой отмены; отмена возвращает полный доступ.
12. После анонимизации email не находится поиском, имя отображается как «Удалённый пользователь», записи журнала операций сохранены и баланс платформы сходится.
