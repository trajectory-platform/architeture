# Список пользователей

## 1. Назначение

Единая точка входа сотрудника к любому аккаунту платформы: ученикам, преподавателям, представителям. Список отвечает на вопрос «найти человека и понять его состояние», карточка — «разобраться и вмешаться».

Сотрудники административной панели в этом списке **не отображаются** — они ведутся отдельным списком в документе [Роли и разрешения](Роли%20и%20разрешения.md), раздел 7.3.

Доступ к разделу: разрешение `auth_user_view`.

## 2. Разграничение с реестрами преподавателей и учеников

Три списка не дублируют друг друга и решают разные задачи.

| Список | Задача | Что в колонках |
|---|---|---|
| **Список пользователей** (этот документ) | Найти аккаунт и работать с ним как с учётной записью | Идентичность, роли, статус аккаунта, вход, сессии |
| [Реестр преподавателей](../Преподаватели/README.md) | Работать с преподавателем как с исполнителем | Верификация, предметы, нагрузка, рейтинг, комиссия, начисления |
| [Реестр учеников](../Ученики/README.md) | Работать с учеником как с обучающимся | Курсы, группы, статус доступа, прогресс, оплаты |

Правило: если колонка описывает **учётную запись** — она здесь; если **учебную или финансовую роль человека** — она в профильном реестре. Карточка пользователя ссылается на профильные реестры, а не повторяет их содержимое.

## 3. Основные сценарии

1. Найти пользователя по фрагменту имени, email, телефона или идентификатору и открыть карточку.
2. Найти все аккаунты с неподтверждённым email за период, чтобы разобраться в проблемах регистрации.
3. Найти заблокированные аккаунты и снять блокировку по итогам разбора обращения.
4. Найти аккаунты в статусе «Удаление запланировано» до истечения отсрочки.
5. Проверить, есть ли у обратившегося человека второй аккаунт с тем же телефоном.
6. Выгрузить срез пользователей для отчёта.

## 4. Экран списка

### 4.1 Колонки

| Колонка | Содержание | Сортировка | По умолчанию |
|---|---|---|---|
| Идентификатор | Короткий вид идентификатора аккаунта, копируется по клику | — | скрыта |
| Имя | Имя и фамилия из профиля; при отсутствии — «Без имени» | да | да |
| Email | Логин пользователя, значок подтверждения email | да | да |
| Телефон | Телефон из профиля | — | да |
| Роли | Метки ролей: Ученик, Преподаватель, Представитель | — | да |
| Статус | Статус аккаунта (раздел 6) | да | да |
| Верификация | Только для аккаунтов с ролью «Преподаватель»: Не подана, На модерации, Верифицирован, Отклонена | да | да |
| Регистрация | Дата и время создания аккаунта | да | да |
| Последний вход | Дата и время последней успешной аутентификации | да | да |
| Способ входа | Пароль, Яндекс ID, VK ID, Google — по фактически привязанным способам | — | скрыта |
| Часовой пояс | Часовой пояс профиля | — | скрыта |

Все даты отображаются в часовом поясе сотрудника с подписью пояса.

Скрытые по умолчанию колонки включаются через настройку состава колонок; выбор сохраняется для сотрудника.

### 4.2 Поиск

Единая строка поиска по подстроке, минимум 3 символа, поиск запускается с задержкой после окончания ввода.

| Поле | Правило сопоставления |
|---|---|
| Имя и фамилия | Вхождение подстроки, без учёта регистра |
| Email | Вхождение подстроки, без учёта регистра |
| Телефон | Вхождение цифр, ввод нормализуется: скобки, дефисы, пробелы и `+` отбрасываются |
| Идентификатор аккаунта | Полное совпадение |

Если строка поиска — полный идентификатор, выполняется прямой переход в карточку.

### 4.3 Фильтры

| Фильтр | Тип | Значения |
|---|---|---|
| Роль | множественный выбор | Ученик, Преподаватель, Представитель |
| Статус аккаунта | множественный выбор | Ожидает подтверждения, Активен, Заблокирован, Удаление запланировано, Удалён |
| Статус верификации | множественный выбор | Не подана, На модерации, Верифицирован, Отклонена |
| Дата регистрации | период | Произвольный период, пресеты: сегодня, 7 дней, 30 дней |
| Последний вход | период | Тот же набор, плюс «Не входил ни разу» |
| Способ входа | множественный выбор | Пароль, Яндекс ID, VK ID, Google |
| Есть представитель | да / нет | Только для роли Ученик |
| Email подтверждён | да / нет | — |

Правила фильтров:

1. Фильтры комбинируются по «И», значения внутри одного фильтра — по «ИЛИ».
2. Активные фильтры отображаются метками над таблицей, каждая снимается отдельно, есть «Сбросить всё».
3. Набор фильтров и поисковый запрос сохраняются в адресе страницы — ссылку можно передать коллеге.
4. По умолчанию список исключает статус «Удалён»; он показывается только при явном выборе.

### 4.4 Действия

| Действие | Где | Разрешение | Подтверждение |
|---|---|---|---|
| Открыть карточку | строка | `auth_user_view` | — |
| Заблокировать / разблокировать | меню строки | `auth_user_block` | да, с указанием причины |
| Завершить все сессии | меню строки | `auth_session_revoke` | да |
| Сбросить пароль | меню строки | `auth_credential_reset` | да |
| Просмотр от лица пользователя | меню строки | `auth_user_impersonate` | да, с указанием причины |
| Выгрузить в таблицу | панель над списком | `auth_user_export` | да |

Массовые действия в этом списке **не поддерживаются**. Обоснование: все действия над аккаунтом требуют указания причины и разбора конкретного случая; массовая блокировка или массовый сброс паролей — операция с несоразмерными последствиями. Массовые операции остаются в разделах, где они осмысленны (зачисления, объявления).

### 4.5 Выгрузка

1. Выгружается текущий отфильтрованный срез со всеми включёнными колонками, включая скрытые в интерфейсе.
2. Ограничение — 10 000 строк за одну выгрузку; при превышении интерфейс предлагает сузить фильтр.
3. Факт выгрузки пишется в [Журнал действий](Журнал%20действий.md) с сохранением примененных фильтров и количества строк.

### 4.6 Постраничная навигация

Размер страницы: 25, 50, 100 строк, по умолчанию 50. Общее количество найденных записей отображается рядом с фильтрами.

### 4.7 Пустые состояния

| Ситуация | Что показывается |
|---|---|
| Поиск не дал результатов | «Ничего не найдено» и кнопка сброса фильтров |
| Поисковый запрос короче 3 символов | Подсказка «Введите не менее 3 символов» |
| Ошибка загрузки | Сообщение об ошибке и кнопка «Повторить» |

## 5. Строка списка: правила отображения

1. Аккаунт в статусе «Заблокирован» отображается приглушённо, статус — красной меткой.
2. Аккаунт в статусе «Удаление запланировано» показывает в колонке «Статус» дату планового удаления.
3. Аккаунт в статусе «Удалён» показывает «Удалённый пользователь» вместо имени, email и телефона.
4. Совмещённые роли выводятся несколькими метками в порядке: Преподаватель, Ученик, Представитель.
5. Колонка «Верификация» пуста для аккаунтов без роли «Преподаватель».

## 6. Статусы аккаунта

| Статус | Код | Смысл | Вход | Уроки и деньги |
|---|---|---|---|---|
| Ожидает подтверждения | `pending_email` | Аккаунт создан, email не подтверждён | Разрешён, доступен только экран подтверждения | Недоступны |
| Активен | `active` | Обычное состояние | Разрешён | Доступны |
| Заблокирован | `blocked` | Заблокирован сотрудником | Запрещён | Будущие уроки отменены, резервы возвращены |
| Удаление запланировано | `deletion_scheduled` | Подана заявка на удаление, идёт отсрочка 30 дней | Разрешён, доступен только экран отмены удаления | Будущие уроки отменены, резервы возвращены |
| Удалён | `deleted` | Персональные данные обезличены | Запрещён | Недоступны |

Переходы:

| Из | В | Кто и чем |
|---|---|---|
| `pending_email` | `active` | Пользователь — подтверждением email |
| `pending_email` | `deleted` | Система — автоочисткой неподтверждённых аккаунтов старше 30 дней |
| `active` | `blocked` | Сотрудник с `auth_user_block` |
| `blocked` | `active` | Сотрудник с `auth_user_block` |
| `active` | `deletion_scheduled` | Пользователь из своего кабинета либо сотрудник с `auth_user_delete` |
| `deletion_scheduled` | `active` | Пользователь отменой заявки либо сотрудник с `auth_user_delete` |
| `deletion_scheduled` | `deleted` | Система по истечении 30 дней |
| `blocked` | `deletion_scheduled` | Сотрудник с `auth_user_delete` |

Статус верификации преподавателя (раздел 3.2 документа [Роли и разрешения](Роли%20и%20разрешения.md)) — независимая величина: заблокированный преподаватель сохраняет статус верификации, разблокировка не требует повторной верификации.

## 7. Правила и ограничения

1. Список не содержит сотрудников административной панели.
2. Аккаунты в статусе «Удалён» скрыты по умолчанию и не участвуют в поиске по имени, email и телефону — искать их можно только по идентификатору.
3. Персональные данные отображаются полностью без маскирования; выгрузка отнесена к опасным действиям и журналируется.
4. Поиск по телефону нормализует ввод: `+7 (999) 123-45-67`, `89991234567` и `9991234567` дают один результат.
5. Список не показывает пароль, его хеш и токены ни в каком виде.
6. Все действия из списка доступны и из карточки пользователя; дублирование сделано намеренно — при разборе обращения сотрудник работает из списка.
7. Действие без соответствующего разрешения не отображается в меню строки.

## 10. Критерии приёмки

1. Поиск по строке `9991234567` находит пользователя с телефоном `+7 (999) 123-45-67`.
2. Поиск по полному идентификатору сразу открывает карточку, минуя список.
3. Ввод двух символов не запускает поиск и показывает подсказку.
4. Фильтр «Роль: Преподаватель» + «Статус верификации: На модерации» возвращает только непроверенных преподавателей; счётчик записей соответствует числу строк при полном перелистывании.
5. Ссылка на список с применёнными фильтрами, открытая другим сотрудником с тем же разрешением, показывает тот же срез.
6. Заблокированный пользователь отображается приглушённо с красной меткой статуса; пользователь с запланированным удалением показывает дату удаления.
7. Удалённый аккаунт не находится по своему прежнему email, но находится по идентификатору и отображается как «Удалённый пользователь».
8. Сотрудник с ролью «Менеджер» не видит в меню строки пункты «Заблокировать» и «Выгрузить».
9. Выгрузка 12 000 строк не выполняется, интерфейс предлагает сузить фильтр.
10. После выгрузки в журнале действий появляется запись с исполнителем, составом фильтра и числом строк.
11. Даты в списке совпадают с часовым поясом, выбранным в профиле сотрудника, при его смене значения пересчитываются.
