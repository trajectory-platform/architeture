# Журнал действий

## 1. Назначение

Неизменяемая запись значимых действий над данными платформы: кто, что, над каким объектом, когда и на каком основании. Журнал отвечает на три вопроса: «кто это сделал», «что было до изменения», «почему».

Журнал — не системный лог. В нём нет технических ошибок, трассировок и отладочной информации: они живут в контуре наблюдаемости ([Архитектура](../../../Архитектура.md), 11.4). В журнале — только действия, у которых есть исполнитель и последствия для пользователя, денег или доступа.

Доступ к разделу: разрешение `auth_audit_view`. Выгрузка: `auth_audit_export`.

## 2. Объём в MVP

В MVP журналируется **узкий обязательный минимум** — действия с необратимыми, денежными и связанными с доступом последствиями. Полное логирование всех изменений в административной панели откладывается за пределы MVP.

Решение снимает расхождение источников: [Верхнеуровневое ТЗ](../../../Верхнеуровневое%20ТЗ.md), 3.1 помечает журнал администраторов как необязательный для MVP, а [Требования к МВП](../../../Требования%20к%20МВП%20версии.md), 2.10 требуют историю изменений ключевых сущностей. Обязательным считается перечень раздела 3; остальное — история изменений на уровне карточек, реализуемая позже.

## 4. Состав записи

| Поле | Обязательное | Содержание |
|---|---|---|
| Идентификатор записи | да | Уникален, не переиспользуется |
| Дата и время | да | Момент выполнения действия; хранится в едином часовом поясе, отображается в поясе смотрящего |
| Тип исполнителя | да | Сотрудник, Пользователь, Система |
| Исполнитель | да, кроме системных | Идентификатор и имя; для сотрудника дополнительно его административные роли на момент действия |
| Признак «от лица» | нет | Заполняется, когда действие выполнено представителем за ученика или сотрудником от лица участников |
| Тип события | да | Код из раздела 3 |
| Тип объекта | да | Пользователь, Административная роль, Урок, Бронь, Операция, Курс, Настройка |
| Объект | да | Идентификатор и отображаемое имя на момент действия |
| Причина | да для действий, требующих причины | Значение из справочника и комментарий сотрудника |
| Изменение | нет | Список изменённых полей: поле, было, стало |
| Результат | да | Успех, Отказ по правам, Отказ по правилам |
| IP-адрес | да | Адрес исполнителя |
| Идентификатор запроса | да | Сквозной идентификатор для сопоставления с техническими логами |

Правила состава:

1. Пароли, хеши паролей, токены и секреты интеграций не пишутся ни в одно поле, включая «было / стало».
2. Отображаемое имя объекта сохраняется на момент действия: после анонимизации аккаунта запись остаётся читаемой.
3. Отказы по правам записываются наравне с успехами — попытка выполнить действие без разрешения является значимым событием.
4. При анонимизации аккаунта записи журнала сохраняются, идентификаторы исполнителя и объекта заменяются на обезличенные.

## 5. Экран журнала

### 5.1 Список

| Колонка | Содержание | Сортировка |
|---|---|---|
| Дата и время | Момент действия | да, по умолчанию по убыванию |
| Исполнитель | Имя и метка типа | да |
| Событие | Человекочитаемое название типа события | да |
| Объект | Тип и отображаемое имя, ссылка на карточку объекта | — |
| Результат | Успех, Отказ по правам, Отказ по правилам | да |
| Причина | Первые символы причины, полностью — в карточке | — |

### 5.2 Фильтры

| Фильтр | Тип |
|---|---|
| Период | Обязательный, по умолчанию последние 7 дней, максимум 12 месяцев за один запрос |
| Тип события | Множественный выбор, сгруппирован по разделам 3.1–3.6 |
| Исполнитель | Поиск по имени и email сотрудника или пользователя |
| Тип исполнителя | Сотрудник, Пользователь, Система |
| Объект | Поиск по идентификатору объекта |
| Результат | Множественный выбор |

Состояние фильтров сохраняется в адресе страницы.

### 5.3 Карточка записи

Открывается боковой панелью. Содержит все поля раздела 4, таблицу изменений «поле — было — стало» и ссылки: на карточку объекта, на карточку исполнителя, на связанную операцию журнала операций (для денежных событий).

### 5.4 Выгрузка

1. Разрешение `auth_audit_export`.
2. Выгружается текущий отфильтрованный срез, ограничение 50 000 строк.
3. Выгрузка сама фиксируется событием `audit_exported`.

### 5.5 Журнал в карточке пользователя

Вкладка «История» карточки пользователя показывает тот же журнал, отфильтрованный по этому аккаунту как объекту **или** исполнителю. Фильтр по объекту и исполнителю на этой вкладке недоступен, остальные фильтры работают.

## 6. Хранение и неизменяемость

| Правило | Значение |
|---|---|
| Изменение записи | Невозможно ни из интерфейса, ни через API |
| Удаление записи | Невозможно ни при каких действиях, включая удаление аккаунта |
| Срок оперативного хранения | 12 месяцев, доступны в интерфейсе и выгрузке |
| Записи старше 12 месяцев | Переносятся в архив, из интерфейса недоступны, восстанавливаются по запросу вне интерфейса |
| Денежные записи | Дублируются событиями журнала операций Billing, который хранится бессрочно и сроком журнала действий не ограничен |

## 7. Правила и ограничения

1. Журнал доступен только на чтение: интерфейс не содержит действий изменения и удаления.
2. Записи создаются в той же транзакции, что и само действие: успешное действие без записи в журнал невозможно.
3. Отсутствие возможности записать журнал прекращает выполнение действия.
4. Причина обязательна для всех событий, у которых она предусмотрена соответствующим экраном; сохранение без причины отклоняется.
5. Секреты, пароли и токены в журнал не попадают.
6. Журнал не заменяет технические логи и не содержит их.
7. Просмотр журнала сам по себе не журналируется; журналируется только выгрузка.

## 8. Права доступа

| Действие | Суперадминистратор | Менеджер |
|---|---|---|
| Просмотр журнала | + | — |
| Просмотр вкладки «История» в карточке | + | — |
| Выгрузка журнала | + | — |

Разрешения `auth_audit_view` и `auth_audit_export` входят только в роль «Суперадминистратор». Выдача их другой административной роли возможна, но требует осознанного решения: журнал содержит персональные данные и историю денежных действий.

## 10. Критерии приёмки

1. Блокировка пользователя создаёт запись с исполнителем, объектом, причиной, IP-адресом и административными ролями исполнителя на момент действия.
2. Изменение имени пользователя сотрудником создаёт запись с таблицей «Имя: было — стало».
3. Попытка сотрудника без разрешения выполнить действие через прямой запрос к API создаёт запись с результатом «Отказ по правам».
4. Ни в одной записи журнала не встречается значение пароля, хеша, токена или ключа интеграции.
5. Отсутствие возможности записать журнал приводит к отказу в выполнении действия, данные не изменяются.
6. После анонимизации аккаунта записи о его блокировке остаются в журнале и читаемы, имя объекта сохранено на момент действия.
7. Ручное пополнение баланса создаёт запись со ссылкой на операцию журнала операций; переход по ссылке открывает эту операцию.
8. Отмена урока представителем за ученика создаёт запись с признаком «от лица» и указанием обоих участников.
9. Фильтр по периоду 13 месяцев отклоняется с пояснением.
10. Выгрузка журнала создаёт собственную запись `audit_exported` с параметрами фильтра и числом строк.
11. Интерфейс журнала не содержит кнопок изменения и удаления; прямой запрос на изменение записи отклоняется.
12. Вкладка «История» в карточке пользователя показывает и действия над ним, и его собственные журналируемые действия.
