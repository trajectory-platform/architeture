# Пользователи и доступ

## Назначение

Раздел обеспечивает управление учётными записями всех пользователей платформы и правами сотрудников административной панели. Здесь же живёт сквозная модель доступа: роли, разрешения, административные роли и правила проверки прав, на которые ссылаются остальные разделы документации.

## Ключевые решения раздела

| Тема | Решение |
|---|---|
| Роли | Учебные: `student`, `teacher`, `representative`. Административные: `superadmin`, `manager`. Несколько ролей на аккаунт; административные не совмещаются с учебными |
| Разрешения | Коды вида `домен_сущность_действие`; `view` и `edit` выдаются независимо; опасные действия — отдельными кодами |
| Доставка прав | Роли и разрешения приходят клиенту в ответе `init` по токену; сервер проверяет права на каждом запросе |
| Административные роли | Роль = набор разрешений в справочнике, а не константа в коде. Поставляются две: «Суперадминистратор» и «Менеджер», остальные заводятся вручную. Сотруднику можно назначить несколько ролей, разрешения объединяются |
| Корневое право | `auth_permission_edit` эквивалентен полному доступу и выдаётся только суперадминистратору |
| Роль преподавателя | Самозаявка → модерация → верификация; до верификации нет каталога и броней |
| Представитель | Отдельный аккаунт, регистрируется первым и заводит ученика с обязательным собственным email |
| Блокировка | Два уровня: полная блокировка аккаунта и снятие преподавателя с публикации |
| Удаление | Анонимизация с отсрочкой 30 дней; финансовая история и факты уроков сохраняются обезличенными |
| Персональные данные | Маскирование не применяется; разграничение — на уровне выдачи `view`, выгрузки журналируются |
| Просмотр от лица | Только чтение, отдельное разрешение, 30 минут, постоянная индикация, запись в журнал |
| Журнал действий | Узкий обязательный минимум в MVP, только чтение, 12 месяцев оперативного хранения |
| Сотрудники | Заводятся только приглашением суперадмина; отдельный адрес и форма входа без внешних провайдеров |
