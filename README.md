# Бизнес-анализ Trajectory

Продуктовая и аналитическая документация платформы онлайн-обучения Trajectory. Документы этого каталога описывают, **что** должна делать система и **почему**; техническая документация бэкенда (контракты, схемы БД, ADR, диаграммы) ведётся отдельно в репозитории бэкенда.

## Базовые документы

| Документ | Содержание |
|---|---|
| [О проекте](О%20проекте.md) | Продукт, аудитория, продуктовая модель, границы, этапы, риски |
| [Верхнеуровневое ТЗ](Верхнеуровневое%20ТЗ.md) | Полное описание системы: бэкенд, админ-панель, кабинеты, интеграции, этапность |

| [Архитектура](Архитектура.md) | Сервисы, взаимодействие, потоки, данные, доступ, нефункциональные требования |

## Конвенции документации

1. **Язык** — русский. Названия технологий, сервисов и событий — английские.
2. **Один документ — один модуль или раздел интерфейса.** Документ отвечает на вопросы: назначение, основные сценарии, состав экранов и полей, статусы, правила и ограничения, права доступа, связи с другими модулями.
3. **Структура документа модуля:**
   - Назначение
   - Основные сценарии
   - Список / экран (поля, поиск, фильтры, действия)
   - Карточка / деталь (вкладки, поля, действия)
   - Статусы и переходы
   - Правила и ограничения
   - Права доступа по ролям
   - Связанные модули
4. **Термины** берутся из [Глоссария](Глоссарий.md). Новый термин сначала попадает в глоссарий, потом используется в требованиях.
5. **Требования формулируются проверяемо**: «должно быть реализовано …», без формулировок вида «удобно», «быстро», «современно».
6. **Ссылки на макеты** и скриншоты кладутся в `assets/` рядом с документом раздела.
7. Документы в статусе заготовки помечены строкой `> Статус: заготовка` — содержимое заполняется в следующих итерациях.
