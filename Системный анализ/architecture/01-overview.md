# 01 — Обзор системы

## Что такое Trajectory

Trajectory — платформа для индивидуальных онлайн-занятий «преподаватель — студент». Продуктовое ядро:

- **Расписание и бронирование**: преподаватель задаёт доступность (включая повторяющиеся слоты), студент бронирует разовые или регулярные уроки; оплата — с внутреннего баланса студента.
- **Комната урока в реальном времени**: большая интерактивная доска (рисование, текст, фигуры, файлы, undo/redo), видео/аудио через WebRTC, чат комнаты, таймер, статус соединения.
- **Чаты вне уроков**: персональные и групповые чаты с историей, вложениями, статусами прочтения; отдельно — тикеты поддержки со статусами.
- **Отчётность и прогресс**: заметки преподавателя после урока, автоматический журнал прогресса (обновление каждые 5 завершённых уроков).

## Ключевые инженерные вызовы

Два требования определяют архитектуру:

1. **Отказоустойчивая синхронизация состояния доски.** Доска — совместно редактируемый документ. Конфликты правок решает CRDT (Yjs): апдейты коммутативны и идемпотентны, порядок доставки не важен, состояние сходится у всех участников. Сервер не интерпретирует содержимое — он relay с персистентностью (см. [05 — Realtime и вайтборд](05-realtime-whiteboard.md) и [ADR-002](../adr/ADR-002-crdt-sync-path-a.md)). Обязательное свойство — восстановление после обрыва соединения без потери данных: переподключившийся клиент догоняет состояние через snapshot + хвост лога.

2. **Низкая задержка медиа.** Видео/аудио идут не через наш бэкенд, а через выделенный WebRTC SFU — **LiveKit**. Бэкенд только авторизует вход в комнату (минтит токены) и принимает вебхуки о событиях комнаты.

Третий вызов — следствие денег в системе: **транзакционная корректность бронирований**. Двойное бронирование исключается на уровне БД (exclusion constraint на `tstzrange`), движение денег — через сагу с холдами и идемпотентностью (см. [04 — Саги и консистентность](04-sagas-and-consistency.md)).

## Технологический стек

| Слой | Технология |
|---|---|
| Бэкенд-сервисы | Go |
| Межсервисный RPC | gRPC (контракты в `proto/` под buf) |
| Шина событий | NATS JetStream |
| Основная БД | PostgreSQL (отдельная БД на сервис) |
| Кэш / presence / fan-out | Redis |
| Файловое хранилище | MinIO (S3-совместимое) |
| Медиа (WebRTC SFU) | LiveKit |
| CRDT | Yjs (клиент); сервер — opaque relay |
| Граница (north-south) | REST через API Gateway, WebSocket через Realtime Service |
| Reverse proxy | Nginx |
| Контейнеризация | Docker / Docker Compose |
| Наблюдаемость | OpenTelemetry, Prometheus, Grafana, централизованные логи |

## Архитектурные принципы

1. **Шесть сервисов для MVP.** API Gateway, Auth, Billing, Core Education, Realtime и Notification. Чаты и отчёты остаются пакетами внутри Core; Notification выделен из-за внешних провайдеров, ретраев и независимого профиля нагрузки ([ADR-001](../adr/ADR-001-microservices-granularity.md)).
2. **Каждый сервис владеет своими данными.** Отдельные базы Postgres, никаких cross-service join. Доступ к чужим данным — только через API владельца или события.
3. **gRPC east-west, REST north-south.** Клиент никогда не говорит по gRPC напрямую ([ADR-004](../adr/ADR-004-grpc-internal-rest-edge.md)).
4. **Синхронно — когда нужен ответ сейчас, асинхронно — когда это факт.** gRPC для запрос/ответ, JetStream для событий (`booking.confirmed`, `lesson.completed`, ...). Публикация — только через transactional outbox ([ADR-003](../adr/ADR-003-nats-jetstream.md)).
5. **Деньги — append-only.** Баланс — сумма строк леджера, не мутируемая колонка. Всё, что двигает деньги или создаёт бронирования, идемпотентно по `Idempotency-Key`.
6. **JWT валидируется локально.** Auth публикует JWKS; gateway и realtime проверяют подпись без сетевого хопа на каждый запрос.
7. **Наблюдаемость с первого дня.** OpenTelemetry-интерсепторы на всех gRPC-вызовах: запрос трассируется от REST-границы через каждый хоп.

## Карта системы

Точки входа для клиента — три, по числу протоколов:

```
Клиент (SPA)
  ├── HTTPS/REST ──► Nginx ──► API Gateway ──► gRPC ──► Auth / Core / Billing
  ├── WSS ─────────► Nginx ──► Realtime Service (события комнат, чат, Yjs-апдейты)
  └── WebRTC ──────► LiveKit (медиа: видео, аудио, screen share)
```
